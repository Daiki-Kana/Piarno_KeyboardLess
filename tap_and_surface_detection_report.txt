1. 打鍵判定・面認識のパイプライン概要
--------------------------------------------------------------------------------

[処理フロー]
Webカメラ映像 (640x480 / 30fps)
  ↓
MediaPipe HandLandmarker (Tasks-Vision, GPU/CPU自動フォールバック)
  ↓
生のランドマーク座標 (rawHands)
  ├─ 特徴量ロガー (featureLogger.ts: 学習データ収集時のみ)
  ├─ 1 Euro Filter 3D 平滑化 (smoothedHands: Canvas描画用)
  └─ 1D-TCN 推論エンジン (tcnTapDetector.ts: 打鍵判定用)
        ↓ 打鍵検知成立 (TapEvent)
     checkAndTriggerTcnTap.ts
        ├─ Web Audio API ピアノ発音 (pianoSynth.ts)
        ├─ 楽譜シーケンサー1音前進 (songSequencer.ts)
        └─ Canvas 打鍵波紋エフェクト追加 (main.ts)

[関連ファイルと役割]
- src/main.ts:
  Webカメラ初期化、requestAnimationFrame によるトラッキング描画ループ管理。
  rawHands (生座標) を tcnDetector に渡し、smoothedHands (平滑化座標) を描画に渡す。
- src/handTracker.ts:
  MediaPipe HandLandmarker をラップ。両手各21点の3Dランドマーク(x, y, z)を取得。
  左右の手を空間X座標(0.46)および画面位置で識別。
- src/tcnTapDetector.ts:
  現在実際に稼働している打鍵判定エンジン。
  過去6フレームの人差し指運動特徴量(6次元)を1D-TCN ONNXモデルで推論し、確率と減速度で判定。
- src/checkAndTriggerTcnTap.ts:
  tcnDetector からの打鍵イベントを受け取り、発音、波紋描画、シーケンサー前進を呼び出す中継部。
- src/tapDetector.ts:
  旧来のルールベース物理減速判定器。現在 main.ts からは一切呼び出されておらず未使用。

2. 机の面・エッジ検出の実装内容
--------------------------------------------------------------------------------

【結論】
机の面認識・エッジ検出・画像処理は「一切実装されていません」。

- 画像処理の有無:
  Canvasのピクセル走査、エッジ検出(Canny/Sobel等)、輪郭抽出、オプティカルフロー等の
  画像解析処理は完全にゼロ行です。
- 机衝突判定の正体:
  机面そのものを視認しているのではなく、「指先が振り下ろされて急停止・急減速した」
  という運動学的挙動のみから衝突を間接的に推測しています。

【背景・机の端との境界線による誤認の発生メカニズム】
- MediaPipeの誤吸着:
  机のヘリや影などの強いコントラスト境界に、MediaPipeの骨格推定ポイント
  (人差し指先端 Tip: 8 や 付け根 MCP: 5) が引っ張られて瞬間的に座標ジッターを起こす。
- 速度・減速度の異常値スパイク:
  1フレームでも座標が境界線に吸着されて急停止すると、差分計算上の局所相対速度 vy や
  減速度 decel = prevVy - currVy に急峻なスパイクが発生し、打鍵と誤認される。

3. 入力特徴量とデータ構造
--------------------------------------------------------------------------------

[対象ランドマーク (右手優先・人差し指のみ)]
- 手首: Wrist (Landmark 0)
- 人差し指付け根: Index MCP (Landmark 5)
- 人差し指先端: Index Tip (Landmark 8)

[特徴量抽出アルゴリズム (tcnTapDetector.ts / featureLogger.ts)]
1. スケール正規化基準長 L:
   手の距離による大きさブレを解消するため、手首〜人差し指付け根のユークリッド距離を基準とする。
   L = sqrt((x5 - x0)^2 + (y5 - y0)^2 + (z5 - z0)^2)

2. 局所相対位置 r(t) (3次元):
   手全体の移動を排除し、付け根を原点とした指先の相対変位ベクトルを L で割る。
   rx = (x8 - x5) / L
   ry = (y8 - y5) / L
   rz = (z8 - z5) / L

3. 局所相対速度 v(t) (3次元):
   前フレームとの相対変位差を時間差分 dt(秒) で除算。
   vx = (rx - last_rx) / dt
   vy = (ry - last_ry) / dt
   vz = (rz - last_rz) / dt

4. 1フレーム特徴量ベクトル (6次元):
   [rx, ry, rz, vx, vy, vz]

5. 入力データ形状 (過去6フレームの時系列):
   直近6フレーム分をキューで保持: shape [1, 6, 6] (Batch=1, Channels=6, TimeSteps=6)

[Z-score 正規化 (public/model_index_scaler.json)]
推論前に各チャンネルから平均値を引き、標準偏差で除算:
- mean: [-0.0163,  0.4485, -0.0638, -0.0142,  0.0559, -0.0097]
- std : [ 0.0577,  0.0833,  0.0827,  0.9126,  1.3444,  0.9329]

[学習済みモデル仕様 (public/model_index.onnx / ml/train_1d_tcn.py)]
- モデル種別: 1D-TCN (時間畳み込みネットワーク, Flatten型)
- ファイルサイズ: 3,494 bytes
- 入力テンソル: "input", shape [1, 6, 6], float32
- ネットワーク構成:
    Conv1d(in=6, out=16, kernel=3, pad=1) + ReLU
    Conv1d(in=16, out=8, kernel=3, pad=1) + ReLU
    Flatten(axis=1) -> [1, 48]
    Gemm/Linear(in=48, out=1) -> [1, 1]
- 出力テンソル: "output", shape [1, 1], float32 (Logit値)
- 確率変換: prob = 1.0 / (1.0 + exp(-logit))

4. 判定ロジックと閾値（ハードコード値）
--------------------------------------------------------------------------------

[打鍵判定条件式 (src/tcnTapDetector.ts)]
```typescript
const prevVy = historySnapshot[4][4]; // 5フレーム前の下向き速度
const currVy = historySnapshot[5][4]; // 最新フレームの下向き速度
const decel = prevVy - currVy;        // 直近減速度

const decelPassed = this.minDecel <= 0.001 ? true : decel >= this.minDecel;

const isTap =
  (timestamp - this.lastTapTimestamp >= this.cooldownMs) &&
  (prob >= this.minProb) &&
  decelPassed;
```

[パラメータ一覧]
- minProb: 0.50 (HUDスライダー調整範囲: 0.10 ~ 0.99)
  1D-TCN モデルが出力する打鍵確率の最低閾値。
- minDecel: 0.30 (HUDスライダー調整範囲: 0.00 ~ 10.00)
  直近2フレームでの下向き速度急減量 (prevVy - currVy)。
- cooldownMs: 100 ms (HUDスライダー調整範囲: 10 ~ 1000 ms)
  打鍵後のチャタリング（連続二重検知）を防ぐ不応時間。

[ベロシティ算出式]
velocity = min(1.0, max(0.35, 0.35 + (max(0, decel) / 10.0) * 0.45 + (prob - minProb) * 0.4))

5. 現在特定されている技術的課題・ボトルネック
--------------------------------------------------------------------------------

1. 机面の絶対基準（接地判定）の欠如:
   机面の高さ（3D空間上の平面方程式や接触Y/Z座標）をトラッキングしていないため、
   空中で指をピクッと止めた動作と、机面を打鍵した動作を区別できず、空中誤認が発生しやすい。

2. 打鍵判定器に平滑化座標ではなく raw 座標を投入している点:
   main.ts で OneEuroFilter3D による平滑化座標 (smoothedHands) を生成しているにもかかわらず、
   tcnDetector.processFrame(rawHands, timestamp) に生座標を渡している。
   このため MediaPipe のジッターがそのまま速度・減速度の巨大なスパイクとなり、誤判定を招く。

3. 人差し指（右手のみ）の単一指制約:
   virtualPositionManager.ts は両手10本の運指管理を備えているが、打鍵判定器 (tcnTapDetector.ts)
   および学習ロジックが「右手」「人差し指 (tipIndex 8, MCP 5, Wrist 0)」にハードコードされている。
   親指・中指・薬指・小指や左手での打鍵は一切検知できない。

4. 学習データの不足と汎化性の低さ:
   ml/dataset/ 内の学習データは計4セッション（正例あり2ファイル、総打鍵数約568フレーム）のみ。
   特定のカメラアングル・特定の人物の手・特定の打鍵スピードに過剰適合しており、
   環境変化（机の高さ、角度、照明）に脆弱。

5. シングルスレッド WASM 推論によるフレームドロップリスク:
   processFrame 内で毎フレーム InferenceSession.run() を await しており、推論中は
   isInferring フラグでロックされるため、処理負荷時に打鍵の最重要フレームが間引かれるリスクがある。

6. 分析結果および改善方針・Step 1 実装記録
--------------------------------------------------------------------------------

[外部アーキテクトによる根本原因分析]
1. 生座標 (rawHands) の直接入力によるノイズ直撃:
   描画には 1 Euro Filter を適用していたが、推論エンジンには生の座標を渡していた。
   机の端などの強コントラスト領域で影等に引っ張られ、1フレームの瞬間移動が発生。
   これが急激な速度スパイク（偽の急減速）として入力され、打鍵と誤認されていた。
2. 「机面」の絶対基準の欠如:
   空間内の平面方程式や接地判定がなく、空中での急停止と机接触が区別不能。
3. 学習データの汎化性能不足:
   4セッション（約568フレーム）の過小データセットによる過学習。

[3段階の改善プランと進捗]

■ Step 1: 推論エンジンに平滑化座標 (smoothedHands) を渡す 【完了】
- 実施内容:
  1. src/main.ts の smoothHandFingertips() において、指先5点のみならず
     全21ランドマーク (allLandmarks: 手首0, MCP5, Tip8を含む) にも OneEuroFilter3D を適用。
  2. src/checkAndTriggerTcnTap.ts で tcnDetector.processFrame() に渡す引数を
     rawHands から平滑化済みの smoothedHands に変更。
- 効果:
  机の端等での座標跳躍ジッターが吸収され、偽の急停止スパイクによる誤打鍵が抑制された。

■ Step 2: 減速度 (decel) のハードコード条件の緩和・見直し 【未着手 / 即時調整可能】
- 課題と方針:
  平滑化座標の導入により速度・減速度の変化がマイルド化するため、打鍵が空振りしやすくなる可能性がある。
  minDecel (減速閾値) の引き下げ、またはモデル確率 (prob) 判定の重みづけを再調整する。
- 補足:
  現在も画面上の白黒ミニマルHUDスライダーから minDecel (0.00〜10.00)、minProb (0.10〜0.99) を
  リアルタイムに調整・テスト可能。

■ Step 3: 手首Y座標による「空中キャンセル」ガードの追加 【未着手】
- 課題と方針:
  手首（Wrist: 0）のY座標が一定以上（画面下部の机面領域）にあることを必須条件とし、
  画面上部・空中での手の動きによる誤爆を物理的に強制ブロックする。

[Step 1 変更対象ファイル]
- src/main.ts
- src/checkAndTriggerTcnTap.ts
